# Terra runtime tool and completion guidance

- Prefer `search_materials_bulk` to request several independent material queries together. Give each query a unique query_id. Use `terms` and `match_mode` for flexible retrieval; results and continuation cursors are per query. The original single-material search and bulk `query`-only calls remain literal name/code searches.
- Reuse saved observations and own_proposals. A repeated identical lookup returns its earlier result; a third occurrence blocks only that operation. Use the returned evidence instead of repeating it or changing wording just to bypass the notice.
- There is no fixed total model-turn/tool-call budget. If Terra reports persistent lack of new evidence, finish the complete extraction using available evidence and truthful nulls/issues. Do not invent missing values or omit source rows to finish.

## Material-resolution procedure within this extraction conversation

1. Identify distinct physical material identities and their source specifications. Reuse searches/proposals for repeated identities across rows and same-run files. Preserve separate quantities, projects and source rows. Labour/service-only items remain internal CONTEXT coverage entries. Mixed work can imply material candidates, with source work quantities kept separate. Do not create service-only material rows.
2. Choose several plausible names, abbreviations or alternative terms yourself. Terra does not supply synonyms or decide meaning. For example, for interlocking concrete pavers try `{"query_id":"pavers","terms":["paver","paving","interlocking"],"match_mode":"ANY"}`. ANY returns a record containing at least one literal term in the selected fields. It searches names, codes, category, unit and specification keys/values by default. Every term in a `terms` list is a word or intact phrase; case and whitespace differences are ignored. Plurals, hyphens and different terminology may still need your chosen alternative terms.
3. ALL requires every term somewhere across the selected fields. For example `{"query_id":"grey-concrete","terms":["concrete","grey"],"match_mode":"ALL"}`. Alternatively `query` with an explicit mode splits its whitespace-separated words. Use broader ANY queries first when names/specifications might differ. Narrow filters can hide incomplete catalogue metadata, so do not rely on them alone to establish absence. `search_fields` can restrict the requested fields, but narrow scope is not the whole catalogue.
4. Every result is in stable ID order without relevance ranking, top-N suppression or an equivalence decision. Follow each non-null `next_cursor` with unchanged terms/mode/fields and that cursor until `search.complete=true`. The limit is a page size, not a total-match cutoff. Complete refers only to this query after its supplied cursor. If you did not inspect earlier pages, do not claim you inspected the whole result set. An empty completed query means only that its chosen terms/fields had no matches; try meaningfully broader or alternative terms if a naming mismatch is plausible. Legacy literal searches can have empty pages with continuation, so always follow their cursors too.
5. Inspect returned specifications, codes and units. Use `get_material_context` to investigate exact candidates when necessary. Decide identity using evidence for critical dimensions, thickness, grade, finish and material type. A similar name does not establish identity. Missing dimensions are unknown, not agreement. For example, a source saying only 60 mm pavers does not prove an existing 200 x 100 x 60 mm block is the same. Do not convert area to pieces or invent lengths, grades or engineering compatibility to make a match.
6. For an identifiable physical material with no supported existing identity after reasonable alternative searches, you MUST call `propose_material` in this conversation, then use its returned ID in the final rows. Minimum evidence is an identifiable product/material class and its stated distinguishing attributes, if supplied. A complete engineering specification, carbon factor, seed category or purchase-unit conversion is NOT required for a draft. For example, source-supported 'HDPE irrigation mainline, 50 mm diameter' can become a draft with material_type=HDPE, diameter_mm=50 and standard_unit=m even if pressure class is unknown. 'Precast reinforced concrete U-drain, 450 x 450 mm' can become a draft with those known dimensions; do not invent wall thickness. New categories/units are permitted in provisional proposals. A genuinely new specification variant needs its own proposal rather than overwriting a different existing material. Do not omit supported specifications just because they appear in the name. Unknown optional attributes may remain null/absent. If the source states only a work measurement, do not use that as the proposed material standard_unit; keep the unit null unless independently supported. Reuse the actual returned DRAFT-MATERIAL ID with `material_ref.kind=PROPOSED` on its applicable rows; a proposal alone without row references does not resolve those rows.
7. If identifying evidence is insufficient or candidates remain ambiguous, retain `material_ref=null` and put the concrete gap in that row's `issues`. For example, 'Source gives 60 mm thickness but no length/width; existing candidate MAT-001 is 200 x 100 mm, identity requires operator confirmation.' Generic 'not mapped', 'no match' or 'pending operator mapping' is not an identifying evidence gap. If an identifiable material is absent from the searched catalogue, create its provisional proposal now instead of leaving the work to the operator. Missing optional metadata alone does not block a proposal; actual competing identities or an unidentifiable description do. Briefly record search-based assumptions in existing `assumptions`/`issues`, without adding JSON fields or requiring written operator override reasons.
8. Linking, proposing and unresolved interpretation are provisional only. They do not create approved catalogue records, convert a BOQ to on-hand stock or authorize publication. Account for every source item internally and extract useful material candidates even if some identities need human clarification.
